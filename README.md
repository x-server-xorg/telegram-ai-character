# tg-ai-bot — ИИ-персонаж в Telegram

Бот-персонаж на DeepSeek для личных и групповых чатов:

- **характер** — один файл `init.txt`, редактируется прямо во время работы,
  правка применяется к следующему же ответу;
- **память диалога** — **одна постоянная сессия DeepSeek на каждый чат**
  (как в character.ai): история хранится на сервере, бот помнит всё
  с самого начала и свои прошлые ответы, локально ведётся архив `messages.jsonl`;
- **в группе** отвечает только на упоминание `@bot`, ответ на его сообщение,
  команду или слово-триггер — но записывает в архив **все** сообщения;
- **в личке** отвечает на каждое сообщение;
- **бэкенд** — веб-чат DeepSeek («редирект»), PoW-челлендж решается официальным
  WASM-солвером;
- **без односложия и эха** — правила живут в `init.txt` и продублированы
  в каждом запросе; если ответ всё равно вышел односложным или повторением
  реплики бота — один раз переспрашивает развёрнутый вариант.

Никакого самообучения, профилей и статистики: бот ровно тот, что написано в
`init.txt`, и помнит ровно то, что было в чате — с самого начала.

## 1. Установка

```bash
cd tg-ai-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Python 3.10+ и **Node.js 18+** — Node нужен для официального WASM-решателя
PoW-челленджа DeepSeek (файлы в `vendor/`), без него веб-чат не пускает запросы.
Проверка: `node --version`.

## 2. Токены

1. **Telegram:** [@BotFather](https://t.me/BotFather) → `/newbot` → токен в `TELEGRAM_BOT_TOKEN`.
2. **DeepSeek:** откройте [chat.deepseek.com](https://chat.deepseek.com), F12 →
   Application → Local Storage → ключ `userToken` → в `DEEPSEEK_TOKEN`
   (либо Network → запрос `.../chat/completion` → заголовок `authorization: Bearer ...`).
   Токен веб-чата живёт порядка суток — периодически обновляйте.
3. **В группах:** @BotFather → `/setprivacy` → **Disable** (иначе бот не видит
   чужие сообщения), затем перезайдите в группу.

## 3. Персонаж: init.txt

`init.txt` — это вся личность бота: имя, характер, правила объёма и языка.
Читается **на каждый запрос**, так что правки применяются сразу.

```text
Ты — живой участник Telegram-чата, а не ассистент. ...
```

## 4. Память и контекст

Каждое сообщение чата дописывается в `data/chats/<id>/messages.jsonl`.
Перед ответом бот собирает промпт:

1. `init.txt` (характер) + инструкции по выводу — system-промпт;
2. **полный транскрипт чата с самого начала** — вся история без ограничений
   по времени и количеству, с отметками времени `[HH:MM]`;
3. сообщение, на которое нужно ответить.

Свои ответы бот тоже пишет в память — поэтому не противоречит сам себе и
помнит, что уже сказал. Единственный физический предел — `MAX_CONTEXT_CHARS`
(размер промпта, контекстное окно модели): он стоит глубоко, и при его
превышении отсекаются только самые старые реплики — свежий диалог всегда
целиком. Всё, что не влезло в промпт, всё равно хранится в `messages.jsonl`.

## 5. Команды

| Команда | Что делает |
|---|---|
| `/start`, `/help` | справка |
| `/forget` | очистить память диалога этого чата (админы, если заданы `ADMIN_IDS`) |

## 6. Настройки (.env)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен бота |
| `DEEPSEEK_MODE` | `web` | `web` \| `official` \| `proxy` |
| `DEEPSEEK_TOKEN` | — | токен веб-чата (для `web`) |
| `DEEPSEEK_API_KEY` | — | ключ API (для `official`) |
| `DEEPSEEK_BASE_URL` | `http://127.0.0.1:8000/v1` | прокси (для `proxy`) |
| `MAX_CONTEXT_CHARS` | `100000` | потолок одного запроса (инструкция + сообщение) |
| `MAX_REPLY_CHARS` | `3500` | максимум символов ответа |
| `TRIGGER_WORDS` | — | слова-триггеры для ответа в группах |
| `TEMPERATURE` | `0.9` | креативность |
| `AI_TIMEOUT` | `180` | таймаут запроса, сек |
| `ADMIN_IDS` | — | команда `/forget` только для них |

### Режимы DeepSeek

| Режим | Как работает |
|---|---|
| `web` (по умолчанию) | Прямой «редирект» на веб-чат: PoW-челлендж решается официальным WASM-солвером (`vendor/deepseek_pow.wasm` через Node.js), запрос уходит на `chat.deepseek.com/api/v0/chat/completion` |
| `official` | Официальный API `api.deepseek.com` — стабильнее и легально, но платный |
| `proxy` | Любой OpenAI-совместимый прокси поверх веб-чата (`DEEPSEEK_BASE_URL`) |

## 7. Запуск

```bash
source .venv/bin/activate
python bot.py
```

Лог пишется в консоль. Ошибки конфигурации выводятся списком и бот не стартует,
пока они не исправлены.

## 8. Проверка без Telegram

```bash
python pow.py        # самопроверка Keccak-256 + наличие WASM-солвера и Node.js
```

### Как устроен PoW

Веб-чат DeepSeek перед каждым `chat/completion` требует заголовок
`x-ds-pow-response` — ответ на `DeepSeekHashV1`-челлендж. В `pow.py` заложены
два пути:

1. **WASM (основной, работает):** `vendor/pow_solver.js` + официальный
   `deepseek_pow.wasm` — тот же модуль, что использует фронтенд DeepSeek.
2. **Python-фолбэк (экспериментальный):** перебор по формуле
   `Keccak-256(f"{salt}_{expire_at}_{nonce}") == challenge` из открытых
   описаний. На актуальных челленджах эта формула **не совпадает** с сервером,
   поэтому фолбэк сработает только при недоступности Node.js — и честно
   сообщит об этом.

## Структура

```
tg-ai-bot/
├── bot.py          # aiogram: приём всех сообщений, триггеры ответа, команды
├── brain.py        # память чата: JSONL-история целиком + сборка промпта
├── deepseek.py     # клиенты веб-чата / официального API / прокси, ретраи
├── pow.py          # PoW DeepSeekHashV1 (WASM через Node + python-фолбэк)
├── config.py       # чтение .env
├── init.txt        # характер персонажа
├── vendor/         # официальный WASM-солвер PoW
└── data/chats/<id>/messages.jsonl   # память диалогов
```
